HTTP STATUS CODES — ШПАРГАЛКА

Эта шпаргалка предназначена для быстрого понимания HTTP-ответов при работе с HTTP-клиентами, recon и ProjectDiscovery httpx.

1. КЛАССЫ HTTP-ОТВЕТОВ


100–199 — Informational
Промежуточная информация. Запрос еще не завершен или сервер сообщает о промежуточном состоянии.

200–299 — Success
Запрос успешно обработан.

300–399 — Redirection
Сервер сообщает о перенаправлении или необходимости другого действия.

400–499 — Client Error
Сервер не может/не хочет обработать запрос из-за проблемы с запросом, аутентификацией, правами, лимитами и т. п.

500–599 — Server Error
Ошибка на стороне сервера или инфраструктуры между клиентом и backend.



2. 2xx — SUCCESS


200 OK

Самый обычный успешный ответ.

Означает:
Сервер получил запрос и успешно вернул ресурс.

Для recon обычно означает:
"На этом URL действительно что-то отвечает."

Пример:
    https://example.com [200]


201 Created

Сервер успешно создал ресурс.

Часто встречается в API.

Пример:
    POST /users
    -> 201 Created

Например, пользователь был создан.


202 Accepted

Запрос принят для обработки, но обработка еще не обязательно завершена.

Часто встречается в API и асинхронных операциях.


204 No Content

Запрос успешно выполнен, но сервер не возвращает тело ответа.

Часто встречается при DELETE или некоторых PUT/PATCH.


205 Reset Content

Сервер успешно обработал запрос и сообщает клиенту, что интерфейс/представление можно сбросить.


206 Partial Content

Сервер возвращает только часть ресурса.

Обычно связан с Range requests, например загрузкой/просмотром больших файлов.


207 Multi-Status

Используется WebDAV для передачи нескольких результатов в одном ответе.


208 Already Reported

Также связан с WebDAV; сообщает, что элементы уже были перечислены в предыдущей части ответа.


226 IM Used

Редкий код, связанный с HTTP Delta Encoding.



3. 3xx — REDIRECTION


301 Moved Permanently

Ресурс постоянно перенесен на другой URL.

Например:

    http://example.com
             |
             v
    https://example.com

Обычно в ответе есть:

    Location: https://example.com/

Для httpx полезно:

    httpx -u example.com -sc -location

Идея:
301 = permanent redirect.


302 Found

Временное перенаправление.

Например:

    /login
       |
       v
    /auth/login

На практике 302 встречается очень часто.


303 See Other

Сервер говорит клиенту получить результат через другой URL, обычно используя GET.

Часто встречается после POST.


304 Not Modified

Ресурс не изменился с момента, указанного в условных запросах клиента.

Обычно связан с кэшированием и заголовками вроде:

    If-None-Match
    If-Modified-Since

Важно:
304 не означает ошибку.


305 Use Proxy

Устаревший код, который исторически указывал на необходимость использовать proxy.

Практически не используется.


307 Temporary Redirect

Временный redirect.

Важное отличие от классического 302:
HTTP method должен сохраняться.

Например:

    POST /api/login
         |
         v
    POST /somewhere


308 Permanent Redirect

Постоянный redirect с сохранением HTTP method.

Упрощенно:

    301 -> permanent redirect
    308 -> permanent redirect + сохраняем method

Это особенно важно для API и POST/PUT/PATCH запросов.



4. 4xx — CLIENT ERROR

400 Bad Request

Сервер считает запрос некорректным.

Возможные причины:

- неправильный URL;
- неправильный формат запроса;
- некорректные параметры;
- malformed headers;
- некорректный JSON;
- другие проблемы синтаксиса запроса.

Важно:
400 не обязательно означает, что endpoint не существует.


401 Unauthorized

Очень важный момент:

401 != "у тебя недостаточно прав".

Семантически 401 означает, что клиент не прошел аутентификацию или должен предоставить корректные authentication credentials.

Пример:

    GET /admin
    -> 401

Смысл:
"Мне нужно, чтобы ты аутентифицировался."

Часто присутствует:

    WWW-Authenticate: Bearer

или:

    WWW-Authenticate: Basic

Для recon/API testing 401 часто говорит о существовании защищенного endpoint.


403 Forbidden

Сервер понял запрос, но отказывает в доступе.

Пример:

    GET /admin
    -> 403

Упрощенное отличие:

    401 -> authentication required
    403 -> access forbidden

Но на практике приложения могут использовать эти коды не идеально, поэтому один status code сам по себе не доказывает конкретную причину.


404 Not Found

Ресурс не найден.

Пример:

    /admin/does-not-exist
    -> 404

Очень важный момент для recon:

404 НЕ всегда означает, что endpoint реально отсутствует.

Приложение может специально отдавать 404 вместо 403, чтобы скрыть существование ресурса.

Поэтому полезно смотреть не только на status code, но и на:

    content-length
    title
    body
    headers
    Content-Type


405 Method Not Allowed

Endpoint существует, но данный HTTP method не разрешен.

Например:

    POST /users
    -> 405

а:

    GET /users
    -> 200

Для API enumeration это очень полезный ответ.

Часто стоит посмотреть Allow header.


406 Not Acceptable

Сервер не может вернуть представление ресурса, соответствующее заголовкам Accept клиента.

Встречается реже.


407 Proxy Authentication Required

Требуется authentication на proxy.


408 Request Timeout

Сервер не дождался полного запроса от клиента.


409 Conflict

Запрос конфликтует с текущим состоянием ресурса.

Часто встречается в API.

Например, попытка создать ресурс, который уже существует.


410 Gone

Ресурс раньше существовал, но был удален, и сервер явно сообщает об этом.

Отличие:

    404 -> ресурс не найден
    410 -> сервер сообщает, что ресурс больше недоступен/был удален


411 Length Required

Сервер требует Content-Length.


412 Precondition Failed

Условие запроса не выполнено.

Часто связано с conditional requests.


413 Content Too Large

Тело запроса слишком большое.

Раньше часто назывался Request Entity Too Large.


414 URI Too Long

URI слишком длинный.


415 Unsupported Media Type

Сервер не поддерживает формат отправленного тела.

Например:

    Content-Type: application/xml

а API ожидает:

    Content-Type: application/json


416 Range Not Satisfiable

Запрошенный диапазон байтов недоступен.


417 Expectation Failed

Сервер не может выполнить ожидание, указанное в Expect header.


418 I'm a teapot

Шуточный HTTP status code, первоначально определенный в RFC 2324 для April Fools' joke.

Может встречаться в реальных приложениях как Easter egg.


421 Misdirected Request

Запрос был направлен серверу, который не может корректно его обработать.


422 Unprocessable Content

Запрос синтаксически корректен, но содержит данные, которые сервер не может обработать.

Очень часто встречается в API.

Например:
JSON валидный, но значение поля не проходит бизнес-валидацию.


423 Locked

Ресурс заблокирован.

Часто связан с WebDAV.


424 Failed Dependency

Запрос не может быть выполнен из-за ошибки предыдущей операции.


425 Too Early

Сервер не хочет обрабатывать запрос, потому что он может быть повторен/replayed.


426 Upgrade Required

Сервер требует перехода на другой протокол.


428 Precondition Required

Сервер требует, чтобы запрос был conditional.


429 Too Many Requests

Клиент отправил слишком много запросов за определенный промежуток времени.

Очень важный код при автоматизированном recon.

Пример:

    429

может означать:

- rate limiting;
- throttling;
- защиту от слишком большого количества запросов.

Смотри также:

    Retry-After:

При работе с автоматизацией важно учитывать rate limits.


431 Request Header Fields Too Large

HTTP headers слишком большие.


451 Unavailable For Legal Reasons

Ресурс недоступен по юридическим причинам.



5. 5xx — SERVER ERROR


500 Internal Server Error

Общая серверная ошибка.

Пример:

    GET /something
    -> 500

Для security testing такой ответ может быть интересным, особенно если определенные параметры стабильно вызывают 500.

Но сам 500 еще не означает наличие уязвимости.


501 Not Implemented

Сервер не поддерживает необходимую функциональность/метод.


502 Bad Gateway

Проблема между proxy/gateway и upstream-сервером.

Например:

    Client
       |
       v
    Nginx
       |
       v
    Application server

Если backend отвечает некорректно или недоступен, proxy может вернуть:

    502


503 Service Unavailable

Сервис временно не может обработать запрос.

Возможные причины:

- maintenance;
- перегрузка;
- upstream недоступен;
- временная недоступность сервиса.


504 Gateway Timeout

Gateway/proxy не дождался ответа upstream.

Условно:

    Client
       |
       v
    Proxy
       |
       v
    Backend

    Backend ------X
              timeout

    Proxy -> 504


505 HTTP Version Not Supported

Сервер не поддерживает используемую HTTP version.


506 Variant Also Negotiates

Редкий код, связанный с content negotiation.


507 Insufficient Storage

Сервер не может сохранить необходимое представление ресурса.

Связан с WebDAV.


508 Loop Detected

Сервер обнаружил бесконечный цикл при обработке запроса.

Также связан с WebDAV.


510 Not Extended

Устаревший/редкий код, связанный с необходимостью дополнительных расширений.


511 Network Authentication Required

Требуется authentication для доступа к сети.

Часто можно встретить в captive portal сценариях.



6. ОСОБЕННО ВАЖНЫЕ КОДЫ ДЛЯ RECON


200
    Что-то успешно отвечает.

201
    Ресурс был создан. Особенно интересно для API.

204
    Успешно, но без body.

301
    Permanent redirect.

302
    Temporary redirect.

307
    Temporary redirect с сохранением method.

308
    Permanent redirect с сохранением method.

400
    Запрос некорректен.

401
    Требуется/не пройдена authentication.

403
    Доступ запрещен.

404
    Ресурс не найден, но это не всегда доказывает отсутствие endpoint.

405
    Endpoint может существовать, но method запрещен.

409
    Конфликт состояния ресурса.

410
    Ресурс явно удален.

422
    Запрос корректен по структуре, но данные не проходят обработку/валидацию.

429
    Rate limiting/throttling.

500
    Server-side error.

502
    Gateway/upstream problem.

503
    Service unavailable.

504
    Gateway timeout.



7. ВАЖНАЯ ИДЕЯ ПРИ АНАЛИЗЕ HTTP


Не анализируй только status code.

Полезно смотреть комбинацию:

    Status Code
    Content-Length
    Content-Type
    Title
    Location
    Server
    Response Time
    Headers
    Body
    Technology fingerprints

Например:

    /admin -> 403 [312 bytes]
    /secret -> 404 [312 bytes]
    /test -> 404 [312 bytes]
    /login -> 200 [8421 bytes]

Сравнение этих характеристик может дать гораздо больше информации, чем один status code.
